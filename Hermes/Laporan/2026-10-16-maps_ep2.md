### MK0.4 — Cek `git status`
Setelah generator, `git status --porcelain` sempat menampilkan ` M Art/Level/ep02_layout_v02.json`. Diperiksa:
```
$ git diff Art/Level/ep02_layout_v02.json      # (kosong)
$ git diff --numstat Art/Level/ep02_layout_v02.json   # (kosong)
$ git ls-files --eol Art/Level/ep02_layout_v02.json
i/lf    w/lf    attr/
$ git config --get core.autocrlf
true
# uji byte index vs file kerja:
index bytes: 202442 | CRLF: 0 | LF-total: 19465
work  bytes: 202442 | CRLF: 0 | LF-total: 19465
raw equal      : True
normalized equal: True
```
Isi file **byte-identik** dengan yang di-commit (generator memang menulis JSON yang sama). `M` muncul **hanya karena line-ending**: `.gitattributes` tidak punya aturan `*.json`, sementara `core.autocrlf=true` membuat checkout menulis CRLF, sedangkan generator menulis LF. File dikembalikan dengan `git restore` (file ini di luar sandbox, read-only) → `git status` bersih lagi:
```
$ git restore Art/Level/ep02_layout_v02.json
$ git status --porcelain     # (kosong)
$ git ls-files --eol Art/Level/ep02_layout_v02.json
i/lf    w/crlf  attr/
```
Kesimpulan: **data di repo = keluaran generator** (bukan beda data). Yang gagal hanya syarat "`git status` bersih" dan penyebabnya config Git Windows, bukan isi JSON. JSON **tidak** di-commit.
